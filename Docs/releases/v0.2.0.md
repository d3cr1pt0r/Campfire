Encrypted server connections, flexible roles and permissions, easier direct messaging, and independent video windows.

## Added

- **HTTPS by default.** Servers use TLS 1.3 and create a persistent identity on first start, without requiring a domain or manually configured certificate. Account actions, messages, files, previews, and call signaling are encrypted in transit.
- **Desktop server identity verification.** The desktop app remembers each server's public-key fingerprint and refuses changed identities. Server, invitation, and owner-setup links can include the fingerprint so the app checks it on the first connection. Connecting with a bare address asks you to confirm the fingerprint.
- **Change password** under **My account**. Changing your password signs out your other devices.
- **Multiple ordered roles per member**, with optional colors. Assigned roles combine their permissions; the highest role with a color determines the member's displayed color.
- **A redesigned role editor** with member assignments, role ordering, channel overrides, and an effective-permissions inspector explaining grants and denials.
- **Private channels and targeted permission overrides.** Set individual channel capabilities to Inherit, Allow, or Deny. Private channels require a visibility grant. Among assigned roles, an explicit allow wins over a deny; role order does not change permission resolution.
- **Delegated administration.** Separate permissions cover assigning lower roles, managing lower roles, banning and restoring lower members, and creating or managing invitations. Delegates cannot grant capabilities they lack or change their own role assignments. Registration settings remain owner-only.
- **Camera and screen-share pop-outs.** Open video in independent windows that can be moved and resized, then return it to the call.
- **Per-channel notification modes:** All messages, Mentions only, or Muted, available in settings.
- **A direct-message list in the left sidebar**, with unread indicators, recent conversations, and pinned conversations. Incoming DMs remain accessible without scrolling through the member directory.

## Changed

- **Default is a fallback role.** It applies only to members with no assigned roles. Assigning any role replaces Default's permissions, overrides, and color entirely; removing the last assigned role restores Default.
- **New roles start with the current Default settings**, including permissions, optional color, and channel overrides, while keeping the name blank.
- **Ownership is separate from roles** and remains protected. Assigning a role cannot grant or transfer server ownership.
- Removed the built-in **Member** role. Existing members retain their other roles or use Default when none remain.
- Replaced Full/Read-only/Hidden channel-access presets with individual permission overrides.
- Members can edit and delete their own visible messages without separate role switches. Thread replies have their own permission and do not require permission to post in the main channel. Channel restrictions do not apply to DMs.
- Renamed the private-call permission to **Start private calls and add participants**.
- Removed friends and friend requests. Start a DM directly from the member list.
- Reduced and matched the top spacing in the channel and member sidebars. Removed the unused Campfire button above the server list, the composer shortcut hint, and the empty-DM greeting and its container.
- Removed the channel-header notification icon and dropdown; notification controls remain in settings.
- Closing the desktop window to the system tray is now enabled by default.
- Remote server addresses default to HTTPS. Saved HTTP addresses migrate to HTTPS, and clients reject remote HTTP connections.
- Opus voice uses constant bitrate to reduce packet-length leakage.
- Hosts can set **PUBLIC_ADDRESS** for shared links, provide certificates with **TLS_CERT_FILE** and **TLS_KEY_FILE**, or use **TLS=off** behind a reverse proxy configured with **TRUST_PROXY**. Loopback HTTP remains available for development with `npm run server:dev`.

## Fixed

- Opening a DM from a member no longer causes a blank screen.
- Message sounds are suppressed only for the conversation currently open in a visible, focused window. Messages in other conversations can still play sounds according to notification preferences.
- Channel visibility and permission changes are enforced across history, attachments, live events, typing, and call access.
- Role assignment and deletion checks prevent indirect privilege escalation, including activating stronger Default permissions by removing the last assigned role.

## Upgrading

- **Update the server and desktop clients together.** HTTPS defaults and the redesigned role/permission model are incompatible with older clients.
- **Back up the entire server data directory before upgrading, including `data/identity/`.** Database migrations run automatically. If a previously established identity key is missing, the server refuses to start. `CAMPFIRE_NEW_IDENTITY=1` explicitly creates a replacement identity; members then need to verify it again.
- **Everyone is signed out once, and unused invitations are revoked**, because earlier versions transmitted session tokens and invitation codes over HTTP. Sign in again and create new invitations. Members who previously used Campfire over an untrusted network should change their password.
- Existing custom roles and channel restrictions migrate to the new model. The built-in Member role and its overrides are removed; members with no remaining roles use the configured Default role. **Review Default, custom roles, and private-channel access after upgrading.**
- Browser users connecting to a self-signed server must accept its certificate warning. Desktop users can verify the fingerprint through a trusted server link. For a bare-address first connection, compare the displayed fingerprint through a trusted channel before accepting it.
- Existing HTTPS reverse-proxy deployments can set `TLS=off` with `TRUST_PROXY`, or supply their certificate and key. Notification preferences carry over to the HTTPS server address.
- Encryption protects transport. Stored messages and files remain readable by the server and anyone with access to its database or backups. Protect the data directory and backups. Downgrading to v0.1.x after migration is not supported.
