Encrypted, tamper-proof connections for every Campfire server, with no domain or certificate setup.

## Added

- **HTTPS everywhere by default.** Servers now serve TLS 1.3 only. Account creation, sign-in, admin actions, messages, files, previews and call setup are all encrypted in transit. On first start a server creates its own key in `data/identity/` and keeps it; there is nothing to buy, configure or renew.
- **Server fingerprints and pinning in the desktop app.** The desktop app remembers each server's identity and refuses to connect if it ever changes, so nobody on the network can impersonate the server or intercept the connection.
- **Server links and invite links.** Links now carry the server's fingerprint (`https://address:3001/#pin=…`), so the desktop app verifies a server from the very first connection without any prompt. Paste a server or invite link into the server field; it fills the address and invitation for you. **Copy server link** is available to everyone under **Server settings**, and owners get **Copy invite link** for each new invitation.
- **First-connection confirmation.** Connecting with a bare address shows the server's fingerprint once and asks you to confirm it.
- **Owner setup link.** New servers print a link containing the setup code and fingerprint. Paste it into the desktop app to create the owner account.
- **Change password** under **My account**. Changing your password signs out your other devices.
- **Constant-bitrate voice.** Calls already used encrypted media; voice packets now keep a constant size so their length doesn't reveal speech patterns.
- `PUBLIC_ADDRESS` sets the address used in printed links and the server's certificate.
- `TLS_CERT_FILE`/`TLS_KEY_FILE` use your own certificate instead (re-read daily for renewals). `TLS=off` is still possible behind an HTTPS reverse proxy named in `TRUST_PROXY`, or on `127.0.0.1` for development (`npm run server:dev`).

## Changed

- The desktop app and browser client refuse `http://` servers other than `localhost`/`127.0.0.1`. Bare addresses like `203.0.113.5:3001` default to `https://`.
- The content security policy only allows encrypted connections to remote servers.
- Browser invite links no longer use a separate "browser link"; the same invite link works in the desktop app and the browser.

## Upgrading

- **This is a breaking release.** Servers switch to HTTPS on the same port. Update the desktop app; clients from v0.1.x can't connect.
- **Everyone is signed out once** and **unused invitations are revoked**, because earlier versions sent session tokens and invitation codes over plain HTTP. Create new invitations after upgrading. Members who used Campfire over the internet before this release should **change their password**.
- Saved `http://` server addresses in the desktop app become `https://` automatically; sign in again.
- **Back up `data/` including `data/identity/`.** Without the identity key the server refuses to start; starting once with `CAMPFIRE_NEW_IDENTITY=1` creates a new identity, after which members need a new server link.
- Browsers show a certificate warning for servers using their own identity. Accept it only for servers you trust, or use the desktop app, which verifies the fingerprint.
- Existing reverse-proxy setups: set `TLS=off` together with `TRUST_PROXY`, or point `TLS_CERT_FILE`/`TLS_KEY_FILE` at your certificate.
- Notification settings carry over to the new `https://` address.
- Stored messages and files are not encrypted by Campfire; use full-disk encryption on the server and keep backups private. Downgrading to v0.1.x after upgrading is not supported.
