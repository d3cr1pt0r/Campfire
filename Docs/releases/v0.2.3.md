Sharper screen sharing after movement, with VP8 preferred for call video.

## Changed

- **Call video now prefers VP8** for both cameras and screen sharing, using Chromium's CPU encoder. Other codecs remain available as fallbacks when needed for compatibility. CPU usage may be higher than with hardware-encoded H.264.

## Fixed

- Addressed screen shares staying blocky for several seconds after moving a window when using NVIDIA's hardware H.264 encoder on a limited-bandwidth connection. Preferring VP8 improves clarity during and immediately after movement in the tested scenario.

## Upgrading

- Update the desktop client and restart it to use the new codec preference. Browser users should reload after their server owner rebuilds and deploys the updated browser assets.
- This release does not change the v0.2.2 database schema or saved settings. Existing data and profiles remain compatible.
- The Windows installer and Linux AppImage support automatic client updates introduced in v0.2.2. Windows portable and Linux tarball users should download the new version manually. See [Desktop updates](../DesktopUpdates.md).
